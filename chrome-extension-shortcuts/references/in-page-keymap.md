# In-page keymap

只在扩展自己的面板/浮层里生效的快捷键。它们不经过 Chrome 的 commands 机制，所以也不享受冲突检测和用户重映射 —— 代价是必须自己把作用域和原生行为处理干净。

## 1. 建立作用域栈，而不是到处监听

给面板、列表、浮层各定义一层键盘作用域，优先级从内到外：

```text
浮层 > 列表 > 面板 > 宿主页面
```

- 命中的层处理按键并阻断继续传播，未命中的再交给外层。
- 面板打开时把按键收进自己的作用域（模态语义）：**未接管的按键只做传播隔离，不做默认行为**。否则在搜索框里打字会漏给站点，触发站点的单键快捷键。
- 浮层打开时整栈让位，避免方向键和 Enter 还在操作背后的列表。

完成标志：同一个键在不同 UI 状态下归属明确，不会同时触发两层动作。

## 2. 尊重原生键盘行为

- 输入框、文本域、选择器内的方向键与 Enter 保留原生语义，除非该控件实现了完整的键盘模型。
- Space、Tab、Escape 在按钮、菜单、输入控件里不能被随意吞掉。
- 区分两个动作：「隔离事件」（`stopPropagation`）和「占用默认行为」（`preventDefault`）。原生控件自己拥有这个键时，只做前者。

完成标志：输入法、选择器、Tab 顺序和辅助技术在面板内都还能正常工作。

## 3. 焦点与可访问性

- 优先使用原生 `button`、`input`、`select`。
- 自定义控件给合理的 `tabIndex` 与 ARIA；自定义列表用 `aria-activedescendant` 或真实焦点同步当前活动项。
- 始终保留清晰可辨的焦点指示 —— 用 CSS 把轮廓去掉是最常见的自伤。
- 快捷键覆盖重要动作即可，不必把每个功能都塞进键盘。

完成标志：只用键盘可以完成核心流程，焦点位置全程可见，鼠标不参与也不中断。

## 4. 与浏览器内置键共存

页面级 keydown 是**先于站点、但晚于浏览器加速表**的：系统与 Chrome 的组合永远先被浏览器处理。

- 官方点名不能干扰缩放组合（`Ctrl/Cmd` + `+`、`-`、`0`）。判据是**没有对它们调用 `preventDefault()`** —— 那一句才代表"这条默认行为归我了"。
- 同理，不要接管浏览器自己的导航键组合（前进后退、标签页切换一类）。

完成标志：面板打开时缩放与浏览器导航键仍然可用。

## 5. 让键位可发现

界面内的键位也要显示**真实绑定**，不是源码里写死的那份：

- 内容脚本里**没有 `chrome.commands`**（该 API 只对扩展页面与后台开放）。需要展示浏览器级命令的真实绑定时，让后台代读一条消息，而不是因为够不着就退回显示默认值。
- 用户改键是即时生效的，不需要重载扩展 —— 所以每次打开帮助浮层都重读一次，别在挂载时读一次就缓存到永远。
- 三种状态要分开显示：**读取中 / 已绑定（显示实际键位）/ 未绑定**。把"未绑定"和"还没读到"混成一种，会用一个按不出来的键误导用户。

完成标志：改键之后，浮层与设置页显示的都是新键；解绑之后不再假装有键。
