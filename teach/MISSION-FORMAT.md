# MISSION.md 格式

`MISSION.md` 位于工作区根目录。它捕获用户学习这个主题的**原因**。每个教学决策——下一步教什么、呈现哪些资源、设计哪些练习——都应追溯至此文档。

## 模板

```md
# 使命：{主题}

## 为什么
{1-3 句话。用户正在追逐的具体现实目标。当拥有这项技能后，他们的生活或工作中会发生什么改变？避免"理解 X"这类抽象表述——挖掘背后的结果。}

## 成功的标志
- {用户将能够做到的一件具体的、可观察的事}
- {另一件具体的事}
- {…}

## 约束
- {时间、预算、既有承诺、学习偏好，任何限定方法边界的东西}

## 不在范围内
- {用户明确不希望在当前追踪的相邻主题——保护最近发展区}
```

## 规则

- **一个工作区一个使命。** 如果用户想学两样不相关的东西，那是两个工作区。
- **具体胜于抽象。** "十月份前跑完半马"优于"变健康"。"给我的团队交付一个 Rust CLI"优于"学 Rust"。
- **对模糊追问到底。** 如果用户无法清晰表达为什么，在写任何东西之前先采访他们。一个糟糕的使命比没有使命更糟。
- **现实转变时修订。** 使命会变。当用户的目标移动了，更新此文件——不要让过时的使命引导未来的课程。
- **保持简短。** 如果 `MISSION.md` 超过一屏，它就不再是指南针，而变成了计划书。
