# API 设计反模式

| 反模式 | 问题 | 替代 |
|--------|------|------|
| 字符串常量代替联合类型 | 无自动补全，typo 到运行时才报错 | `type Status = "idle" \| "loading" \| "done"` |
| 返回结构随参数变化 | 调用方需类型收窄，增加心智负担 | 始终返回一致结构，多余键为 `undefined` 也好过变形 |
| 配置散落多处 | 调用方猜测选项传在第几个参数的哪个字段 | 收敛到一个 `options` 对象 |
| 暴露内部实现细节 | 换实现时破坏使用者代码 | 只暴露行为，不暴露内部状态 |
| 版本号体现在 API 路径 | 同时维护 N 个版本，最终成兼容债务 | API 自身通过渐进式增强保持向后兼容 |
