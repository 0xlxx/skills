# 转录：把声音变成可用文字稿

**字幕和音频是两条独立的轨。** 有字幕就直接取，没有就自己听写——字幕缺失从来不是终点。

## 步骤

1. **字幕优先。** 先弄清源站有没有字幕轨、有哪些语言。
   完成标志：拿到确切的语言代码，或确认目标语言确实没有字幕轨。有走 A，没有走 B。
   - **A 有字幕** → 直接下载（命令见 [`references/commands.md`](references/commands.md)）；拿到空文件或下载失败时转 B。
   - **B 无字幕** → 继续第 2 步。
2. **建词表。** 从标题、简介、章节表、代码仓库、官方文档里抄出这份素材的专有名词、产品名、缩写、参数名。
   完成标志：一份逗号分隔的词表。第二遍的收益全靠它，所以它在听写之前就要就位。
3. **取音轨并归一化。** 下载音频（本地文件跳过下载），转成 16kHz 单声道 WAV。
   完成标志：WAV 能被 `ffprobe` 读出音频流，时长与源文件相差不超过 1 秒。
4. **听写两遍。** 第一遍裸跑做基线，第二遍带词表跑。
   完成标志：`transcript.pass1.*` 与 `transcript.*` 都非空，且第二遍的 prompt 包含词表里每一项。
5. **两遍互证，定点校对。** 优先处理两版**不一致**的地方——那是最可能的错处；两版一致处做抽查。每一处改动都要有外部锚点（官方文档、章节标题、配置文件）支撑。
   完成标志：专有名词、数字、缩写逐项核对过，并写出「原文 → 改成 → 依据」。规则见 [`references/proofreading.md`](references/proofreading.md)。
6. **交付。** 文字稿与时间轴，外加三项证据。
   完成标志：一次给出 `txt`、`srt`，以及**词表 / 改动清单 / 残留不确定**——使用者要能判断哪些字可信、哪些还要自己听。

步骤 1–4 由 [`scripts/transcribe.sh`](scripts/transcribe.sh) 一次跑完：探测字幕、取音轨或字幕、归一化、两遍听写，每次运行写进独立的 `run.XXXX` 目录。步骤 5–6 由 agent 完成。

## 为什么是两遍

Whisper 不是查字典，是**按声音猜字**。中文技术内容里最先崩的就是专有名词——它听懂了 `mihomo`，却要决定写哪几个汉字，于是写成「米红木」；`no-resolve` 成了「弄水造物」。

第二遍带着词表跑，等于提前把猜字空间收窄。两版之间的差异本身就是情报：不一致的地方就是要重点校对的地方。

模型选择、命令参数、平台差异见 [`references/commands.md`](references/commands.md)。
