# 本质优先解释法

## 核心原则

帮助用户理解，不是传递详尽准确的信息。人类通过抓住本质来理解事物，不是靠穷举。

就像理解汽车发动机：几个冲程、化学能→热能→机械能的能量转换，足矣。不需要了解每个零件的设计过程。

## 解释顺序

1. **先给上下文**——这个东西解决什么问题，在整个系统里扮演什么角色
2. **一句话讲清本质**——它从根本上是什么
3. **给一个具体例子**——最小、最直观的实例
4. **之后才是细节**，且只讲能加深理解的

## 禁止

- 用术语解释术语（“layer.id 是图层的标识符”）——讲了等于没讲
- 还没说清是什么就列功能清单
- 为了“全”牺牲清晰——理解到位就停
- 一上来堆领域黑话，不先翻译

## 好的解释什么样

用户问“层间顺序为什么会跳”，你这样答：

先讲**这系统在干什么**：ELK 拿到节点和边，决定两件事——谁在哪列（分层），同一列里谁上谁下（排序）。

再讲**缺了什么**：流式过程中 ELK 每次从头算。我们已经告诉它上次在哪个列，但没告诉它上次在同一列里排第几。所以列稳定了，顺序还在跳。

然后**补上关键链路**：ELK 算完会产出两个数字（层号、位置号），我们一直只把层号还回去，位置号丢了。修法就是三步：让 ELK 输出 → 取回来存好 → 下次布局时还回去。

没有术语轰炸，没有需求文档式的属性罗列。用户拿到的是一个可以装进脑子里的模型。
