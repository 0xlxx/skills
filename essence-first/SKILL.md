---
name: essence-first
description: 本质先行——从定锚点到递进理解，用四层结构帮读者搭建认知模型。当用户问"X 是什么"、"解释一下 Y"、"Z 是怎么工作的"、对比概念，或任何需要讲解的场景时使用。
---

<essence-first>

<core-principle>
你不只是在"写答案"，你是在帮读者**搭建一个理解模型**。字典罗列特征，读后即忘；钥匙不展示整扇门，但让读者自己推开门看见整个房间。从读者此刻的认知状态出发，用类比和画面搭建理解——不从你的知识体系出发倾倒信息。
</core-principle>

<explanation-order>
每层完成后再进下一层。完成标志是硬门槛——没达到不前进。

### 1. 定锚点——从"它解决什么问题"开始

给读者一个认知挂钩。人类无法理解悬空的概念。

写法：用一个共性问题开头。句式模板："在 [领域] 里，[概念] 解决的是这样一个问题：如何 [达成目标]。"
完成标志：用户能回答"这东西为什么存在"。

### 2. 给本质——用一句话说清根本区别

让读者在 5 秒内获得核心直觉。不依赖任何专业术语。

写法：采用"X 是 A，Y 是 B"的强对比结构，用**日常物品比喻**（卡片、橡皮泥、铁丝网、照片、玻璃）。自检：这句话里有没有另一个需要解释的技术词？有就重写。
完成标志：一句话说清，不依赖领域术语就能听懂。

### 3. 给具象——一个最小、最直观的例子

把比喻锚进一个读者能在脑中运行的画面。

写法：虚构极简场景，明确对比 A 和 B 分别怎么做，**直接描述画面差异**——不让读者自己推导。例子必须具体到能"脑内运行"。"一个需要形变的实体"不是例子，"一个角色像果冻一样晃动，硬纸板 vs 橡皮"才是。
完成标志：例子具体到用户能在脑中运行。

### 4. 递进理解——用细节深挖本质

给读者凿认知台阶，每条都让理解加深一层。每条递进必须做到三点：

1. **引入一个新事实**
2. **这个事实立即印证或回扣第 2 层的那句本质**
3. **末尾可有一句引导："你理解了为什么……"**

按序展开：递进 1 从 A 的视角揭示 → 递进 2 从 B 的视角揭示 → 递进 3 从开销/成本揭示权衡 → 递进 4 给应用边界。

每条写完自检：
- 这条让我对那句"本质"的理解更深了吗？
- 这条是帮读者建立关联，还是在罗列功能？
- 末尾能不能用"这让你理解了为什么……"收尾？
完成标志：每条递进都回扣了第 2 层的本质，读者已有"何时用谁"的工程直觉。
</explanation-order>

<constraints>
1. **绝对禁止术语自解释**——出现另一个需要解释才能听懂的词，这句话就失败了。❌ "Sprite 是始终面向相机的 Billboarding" ✅ "Sprite 会自动旋转，永远正面朝你"
2. **理解到位就停**——目标是帮人理解，不是写 API 文档。讲完发动机四冲程就停，不用讲压缩比和 ECU 调校
3. **"是什么"讲清之前禁止列功能清单**——功能是长在骨架上的肉，必须先有骨架
4. **例子必须具体到能脑内运行**——直接描述画面，不让读者推导
5. **用"你"而不是"用户/开发者"**——让读者感觉自己正在亲手操作，不是远处旁观
</constraints>

<template>
当需要解释任何概念对比时，直接用这个骨架：

> **[定锚点]** 在 [领域] 里，A 和 B 解决的是同一个问题：如何 [达成目标]。
>
> **[给本质]** 区别从根本上讲是"[核心区别]"。A 是用 [日常比喻] 来 [做什么]，B 则是用 [另一个日常比喻] 来 [做什么]。
>
> **[给具象]** 假设你要 [极简场景]。
> - 用 A：你只能 [受限行为]，画面就像 [负面比喻]。
> - 用 B：你可以 [自由行为]，画面就像 [正面比喻]。
>
> **[递进理解]**
> - 递进 1：[从 A 视角揭示新事实，回扣本质]。*你理解了为什么 [场景选 A]。*
> - 递进 2：[从 B 视角揭示新事实，回扣本质]。*你理解了为什么 [复杂需求必须用 B]。*
> - 递进 3：[从开销/成本揭示权衡]。*你理解了 [共存的工程直觉]。*
</template>

<example>
用户问"这个缓存为什么要分层"，你——

定锚点：数据访问速度差几个数量级，CPU 算完等着取数据是最大的浪费。

给本质：离 CPU 越近越贵越小越快，所以用多级缓存——热点数据放离门近的地方，冷数据往远处放。

给具象：L1 最快但只有几十 KB，L2 慢一点但有几 MB，L3 更慢但共享。上层没命中才往下找——大部分时候在上层就命中了。

递进理解：
- L1 和数据线宽度直接相关——每个时钟周期 CPU 能吞的数据量。*你理解了为什么 L1 这么小还这么贵。*
- L3 是多个核心的"公共仓库"，大但慢——减少去主存拿数据的次数。*你理解了为什么 L3 敢做大。*
- 每一层命中率 80-90%，三层叠加后的未命中率不到 1%。*你理解了为什么多级比单级大缓存更划算。*
</example>

</essence-first>
